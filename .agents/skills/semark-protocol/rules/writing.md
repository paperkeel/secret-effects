# Semark writing

Use these rules for Semark signatures, repository instructions, audit findings, install
reports, and skill instructions. Treat this module as self-contained. Do not load a
separate writing skill.

## Signatures

- Start each summary with a concrete verb in the simple present, such as `Creates`,
  `Validates`, or `Persists`.
- Describe behavior that is visible across the documented boundary.
- State each responsibility and boundary separately.
- Explain the domain meaning or constraint of an input, result, or failure.
- Do not repeat an identifier or type without new information.
- Include a side effect, invariant, constraint, assumption, or interaction only when
  implementation evidence supports it.
- Do not list symbols, imports, or exports. Do not describe implementation steps.

## Protocol text

- Use the imperative form for an agent action.
- Put one rule or action in each sentence. Keep one topic in each paragraph.
- Use exact paths, commands, tags, and finding categories.
- Separate a requirement from its explanation.
- Write each skill description as a selection rule for the agent.
- State when the agent must use the skill.
- Write each skill body as direct instructions to the agent.
- Do not explain skill benefits to a user.

## Language

Use active voice, simple tenses, direct verbs, and consistent domain terms. Use short,
common words when they preserve the technical meaning. Use American spelling. Do not
use contractions, semicolons, phrasal verbs, marketing adjectives, or speculation.

Preserve identifiers, error names, values, units, conditions, and scope qualifiers. Do
not remove technical facts to meet a length limit. The applicable signature rule sets
all word and sentence limits.
